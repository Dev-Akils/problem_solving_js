Cluster mode in Node.js allows us to create multiple worker processes that can handle incoming requests concurrently. It helps utilize multiple CPU cores and improve the application's ability to handle a higher volume of requests.




2. Understand one important point
- Concurrency: Multiple requests can make progress without having to wait for each other unnecessarily.
- Parallelism: Multiple workers can execute on different CPU cores at the same time.
Cluster mode helps with both request-handling capacity and parallelism. However, actual performance
 depends on your workload and system resources.

A memory leak in React occurs when resources or references are retained unnecessarily after a 
component is no longer needed. Common causes include uncleared timers, event listeners, subscriptions, 
and unnecessary ongoing asynchronous operations. We can prevent these issues by using the cleanup function 
returned from useEffect to clear timers, remove listeners, cancel requests where possible, and unsubscribe from 
external resources.                                                                                              
   4. How do we prevent memory leaks?
- Clear timers using clearInterval() or clearTimeout().
- Remove event listeners using removeEventListener().
- Cancel supported API requests using AbortController.
- Unsubscribe from subscriptions and disconnect observers when they are no longer needed.
- Avoid retaining unnecessary references to large objects.

1. What is data consistency?
Data consistency means keeping data correct, accurate, and synchronized across the database.
For example, imagine a banking application.
- User A has ₹5,000.
- User transfers ₹1,000 to User B.
- User A should have ₹4,000.
- User B should receive ₹1,000.
If the money is deducted from User A but not credited to User B, the data becomes inconsistent.
2. How does MongoDB maintain data consistency?

1. Atomic operations
MongoDB guarantees that a single-document write operation is atomic.
 Either the entire operation on that document succeeds, or it does not partially apply.
Example: updating a user's balance in one document.


2. Transactions
If an operation updates multiple documents, MongoDB supports multi-document transactions so 
the changes can commit together or be rolled back.
Example: deducting money from one account and crediting another.


3. Read and write concerns
These settings control the acknowledgment required for writes and the consistency guarantees for reads,
 especially when MongoDB uses replica sets.
Example: using writeConcern: { w: "majority" } to wait for acknowledgment from a majority of voting members.


4. Schema validation
MongoDB can enforce rules for document fields and data types to prevent invalid data from being inserted or updated.



3. Interview question and answer
Question: How do you maintain data consistency in MongoDB?
A good interview answer:
"In MongoDB, we maintain data consistency using atomic operations, transactions, read and write concerns, 
and schema validation. Single-document operations are atomic by default. For operations involving multiple documents, 
we can use transactions to ensure that all changes are committed together or rolled back if something fails. 
We can also use schema validation to prevent invalid data."

We prefer functional components over class components in modern React because they 
require less boilerplate code, are easier to read and maintain, and support Hooks such as 
`useState` and `useEffect`. Hooks also allow us to reuse stateful logic through custom Hooks. 
Class components use lifecycle methods and `this.state`, whereas functional components use Hooks 
to manage state and side effects. Both are supported by React,
 but functional components are recommended for new development.
